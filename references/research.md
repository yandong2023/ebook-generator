# Research and Source Handling

Use this reference for nonfiction and source-driven books.

## Source ledger

Maintain `sources.md` as a working ledger. For each source record:

- stable title
- author/organization
- publication date when known
- URL or file name
- source type
- key claims used
- chapter(s) where used
- quotation status: paraphrase / short quote / user-owned text

## Research workflow

1. Start with the book's claims, not a giant undirected search.
2. For each chapter, list the factual questions that must be resolved.
3. Prefer primary sources for technical, scientific, legal, regulatory, financial, and platform-specific claims.
4. Distinguish facts from interpretation.
5. Record uncertainty and conflicts between sources.
6. Do not cite a source you did not inspect.
7. When information can change, verify it close to publication time.

## Transforming articles, transcripts, and notes

Do not make one source equal one chapter by default. Instead:

1. extract atomic ideas and claims;
2. cluster them by reader problem/theme;
3. remove duplicates;
4. identify contradictions and missing context;
5. design a reader-first chapter structure;
6. write original synthesis using the ledger for traceability.

For transcripts, remove filler, repeated stories, sponsor segments, and transcription artifacts before synthesis. Verify names, numbers, and technical terms against reliable sources when they matter.

## Quotations

Use quotations only when the exact wording is important. Keep third-party quotations short, attribute them clearly, and prefer paraphrase for ordinary factual material. Never manufacture a quotation from a paraphrase.

## Citation styles

Respect the user's requested citation style. If none is requested, use unobtrusive endnotes or a source list for general nonfiction. Keep raw research URLs out of the prose unless useful to the reader.
